This page uses the 20 short-answer review questions provided for the programming final. It covers Git, software architecture, HMI, SEMI E10, OEE, InfluxDB, Grafana, and Docker.

20 Short Answers

Q1. In the kitchen analogy, what does the staging area represent and which Git command moves a file into it?

The staging area is where Git prepares changes before committing them. In the kitchen analogy, it is the cutting board. The command is git add .

Q2. What does git init do, and what artifact does it create in your project folder?

git init turns a normal folder into a Git repository. It creates a hidden .git folder that stores commits, branches, history, and Git configuration.

Q3. Explain the three-zone mental model of Git: working directory, staging area, and commit history.

The working directory is where files are edited. The staging area is where selected changes are prepared using git add. The commit history is where permanent snapshots are saved using git commit.

Q4. What is the difference between git diff and git status?

git status shows the general state of the repository, such as modified, staged, or untracked files. git diff shows the actual line-by-line changes inside the files.

Q5. What does git restore do and when would you use it?

git restore discards uncommitted changes and restores the file to the last committed version. It is used when edits were a mistake and should be undone.

Q6. What is a Git branch and why are branches described as cheap and isolated?

A branch is a separate line of development. Branches are cheap because they are lightweight pointers to commits, and isolated because changes on one branch do not affect another branch until merged.

Q7. What does git clone do and how is it different from git init?

git clone downloads an existing repository with its files, history, and remote connection. git init starts a new empty repository in the current folder.

Q8. What is a remote in Git, and what do git push and git pull do?

A remote is a shared repository stored on a server such as GitHub. git push uploads local commits to the remote. git pull downloads and integrates new commits from the remote.

Q9. Which are the SEMI E10 equipment states? Describe them.

The SEMI E10 states are Productive, Standby, Engineering, Scheduled Downtime, Unscheduled Downtime, and Non-Scheduled Time.

Q10. How are the SEMI E10 defined buckets of time represented?

SEMI E10 represents equipment time as mutually exclusive time buckets. Total time is divided into Operations Time, Equipment Downtime, and Non-Scheduled Time.

Q11. What is an HMI and what are the three rules of good HMI design?

An HMI is the operator screen for monitoring and controlling a machine. Good HMI design shows only needed information, makes abnormal states clearly visible, and never shows false machine states.

Q12. What is the difference between Back End and Front End, and how do they map to the simulation files?

The Back End contains logic, data, rules, and decisions. The Front End displays information and receives user input. In this project, src/main.py contains the Python logic and Tkinter HMI.

Q13. What is the role of the Abstract Base Class Station in a production line backend?

An abstract base class Station defines a common contract for all production stations. Each station must implement its own process method, while the production system can treat all stations consistently.

Q14. What is the SEMI E10 standard and what are three machine states used in a production-line demo?

SEMI E10 is a manufacturing standard used to classify equipment time and machine states. Example demo states are Productive, Standby, and Unscheduled Downtime.

Q15. What does OEE stand for, how is it calculated, and what is the world-class target?

OEE stands for Overall Equipment Effectiveness. It is calculated as Availability × Performance × Quality. A world-class OEE target is about 85% or higher.

Q16. What is a Manufacturing Execution System and at which ISA-95 level does it operate?

A Manufacturing Execution System monitors and coordinates production on the factory floor in real time. It operates at ISA-95 Level 3.

Q17. What is a Finite State Machine and where is one applied in production animation?

A Finite State Machine is a model where an object can be in exactly one state at a time. It can be applied to product movement stages and machine states.

Q18. In the InfluxDB/Grafana stack, which component writes data, which stores it, and which visualizes it?

The Python producer writes data, InfluxDB stores the data, and Grafana visualizes the data.

Q19. What is Docker and what are its main applications?

Docker is a containerization platform that packages an application with its dependencies into a portable container. It is used for development environments, deployment, microservices, CI/CD, and multi-container applications.

Q20. Describe how the architecture of your project looks like.

The HMI allows the user to start, stop, reset, and monitor the system. The Python production line handles manufacturing stages, quality control, counters, and defects. Data is sent to InfluxDB and visualized in Grafana. InfluxDB and Grafana run inside Docker containers.
